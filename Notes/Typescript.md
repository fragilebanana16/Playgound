

### 元组（Tuple）与数组（Array）的区别
两者在运行时均为普通 JS 数组，但在 TS 类型系统中约束粒度不同：

数组（如 `T[]`）长度不固定且所有元素共享同一类型（或联合类型），不限制元素顺序；

元组（如 `[T1, T2]`）长度固定，且为每个索引位置独立指定严格的类型与顺序（支持可选元素 `?`、剩余元素 `...` 及 `readonly` 修饰）

### `const enum`（常量枚举）
`const enum` 是在编译阶段直接将枚举引用内联替换为其对应字面量值

### `enum` 的多处定义（声明合并）
同名 `enum` 支持在多处重复定义并自动合并为一个完整枚举

### `void`、`never` 与 `undefined`、`null` 的区别
`undefined` 和 `null` 是各含唯一同名值的单值类型，分别表示未定义和主动置空；

`void` 主要用于函数返回值，表示函数正常结束但不提供可用返回值；

`never` 是不包含任何值的空集底部类型，代表永远无法正常抵达终点的函数（如抛异常、死循环）或类型收窄后不可能出现的分支

### `undefined` 与 `null` 类型
`undefined` 和 `null` 在 TS 中既是原始值也是独立的单值类型，各自仅包含唯一对应的同名值；

### `object`（小写）与 `Object`（大写）的区别
小写 `object` 表示所有非原始类型（排除 `string`、`number`、`boolean`、`bigint`、`symbol`、`null`、`undefined` 后的引用类型）；

大写 `Object` 描述的是具有 `Object.prototype` 方法（如 `toString`）的实例，在 TS 中等价于 `{}`，可接收除 `null` 和 `undefined` 外的任意值（包含原始类型），日常开发中应==严禁使用大写 `Object`==

### 避免使用 `{}` 或 `object` 作为类型注解
类型范围过于宽泛且不符合直觉，几乎失去了静态类型检查的意义

### `const` 与 `readonly` 的区别
`const` 是 JS 原生关键字，作用于变量本身，防止变量引用被重新赋值（运行时和编译时均生效），但无法阻止对象内部属性的修改；`readonly` 是 TS 类型修饰符，作用于==**对象属性**==或数组元素（仅在编译期进行类型检查，编译后被擦除），用于防止特定属性被修改

### 必填属性与可选属性（`?`）
对象类型中默认所有属性均为必填，赋值时必须完整提供所有声明的属性，否则会触发缺失报错；若允许某属性省略，可在属性名后加 `?`（如 `age?: number`）标记为可选属性，其等效类型为 `原类型 | undefined`

### `const` 带来的类型收窄（抑制类型拓宽）
使用 `const` 声明原始类型变量时，因变量无法被重新赋值，TS 会抑制类型拓宽，直接将其推导为最精确的字面量类型（如 `const a = 'hi'` 推导为 `'hi'` 而非 `string`）；但对于对象或数组，`const` 仅锁定引用，内部属性仍会被拓宽，需配合 `as const` 才能彻底收窄内部属性

### `typeof` 与 `instanceof` 的区别

`typeof` 返回表示类型的字符串，主要用于判断基础原始类型（如 `string`、`number`、`boolean`）及 `function`，但对所有引用类型和 `null` 均返回 `'object'`；

`instanceof` 返回布尔值，通过检查构造函数的 `prototype` 是否在对象的原型链上，专门用于判断具体对象或自定义类的实例（对原始类型无效）

### `bigint` 字面量语法

在整数字面量末尾添加 `n` 后缀（如 `1234n`）即可表示 `bigint` 类型，用于突破 `number` 类型 $2^{53}-1$ 的最大安全整数精度限制；注意 `bigint` 仅支持整数，且不能直接与 `number` 混合进行算术运算。

### 隐式 `any` 报错

开启 `strict` 或 `noImplicitAny` 时，TS 无法推断类型而兜底为 `any` 会直接报错

### `any` 与 `unknown` 的区别
两者都是顶级类型（可接收任意值），但 `any` 会彻底关闭类型检查，允许随意操作且容易引发运行时错误；`unknown` 则是类型安全的，使用前必须先通过类型收窄（如 `typeof`、`instanceof`）或类型断言确定具体类型。

### 字面量类型与对象字面量
字面量类型是仅表示单个具体值的类型（如 `'tom'`）；对象字面量需区分代码位置：写在值位置（如 `= { name: 'tom' }`）时是创建对象实例，写在类型标注位置（如 `: { name: 'tom' }`）时则是对象字面量类型，不仅约束对象结构，还会把属性值锁定为该具体的字面量

### `const` 与 `let` 的类型推断差异（类型拓宽）
使用 `let` 声明原始值（如 `let c = true`）时，由于变量后续可修改，TS 会触发类型拓宽将其推断为宽泛的 `boolean`；而使用 `const` 声明（如 `const c = true`）时，因常量不可重新赋值，TS 会将其精确锁定为字面量类型 `true`

### 基础原始类型优先使用类型推导
对于 `boolean`、`number`、`bigint`、`string` 变量，应尽量依赖 TS 自动类型推导而非手动标注（如直接写 `let a = 1` 而非 `let a: number = 1`），这样既能减少代码冗余，也能避免用 `const` 声明时手动注解破坏字面量类型的精确推断
